<<< QUESTION 1 >>>

What are special tokens like <|endoftext|> and <|unk|> used for in a tokenizer's vocabulary?


### WRITE ANSWER BELOW ###

<|endoftext|>: marks where the text ends (this is usually used to concatenate multiple unrelated texts, e.g., 
two different Wikipedia articles or two different books, and so on). Similarly EOS.At inference, it also signals 
generation should stop.

<|unk|>:  to represent words that are not included in the vocabulary. The modern tokenizers like BPE,WordPiece rarely hit 'unk'
because any unknown word can be decomposed into known subwords/bytes.

Explain the concept of "temperature" in text generation. How do low and high temperature
values affect the model's output, and give the softmax formula showing where temperature is
applied.

### WRITE ANSWER BELOW ###

The temperature parameter is used to determine the randomness of the model in picking the next token.

temperature Scaling divides logits by temperature(T) before softmax.

P(token_i) = exp(logit_i / T) / Σⱼ exp(logit_j / T)
Lets say it calculates the logits of 3 tokes as below 

P(A_logit)=2
P(B_logit)=3
P(C_logit)=4

Now if T<1 lets say 0.3
P(A)=exp(2/.3)/(exp(2/.3)+exp(3/.3) + exp(4/.3))=0.001
P(B)=exp(3/.3)/(exp(2/.3)+exp(3/.3) + exp(4/.3))=0.03
P(C)=exp(4/.3)/(exp(2/.3)+exp(3/.3) + exp(4/.3))=0.96

So when T<1 then logits gets amplified.Gaps widen and top tokens dominate.

Similarly when T>1 then say T=2 then logits get compressed.Gaps shriks. Hence token distribution becomes closer.
P(A)=exp(2/2)/(exp(2/2)+exp(3/2) + exp(4/2))=0.18
P(B)=exp(3/2)/(exp(2/2)+exp(3/2) + exp(4/2))=0.30
P(C)=exp(4/2)/(exp(2/2)+exp(3/2) + exp(4/2))=0.50

Lastly when T=1 then standard softmax no modification.
P(A)=0.09
P(B)=0.24
P(C)=0.67

Hence T<1 is more detereministic answer and T=2 is more volatile/random answer and T=1 is unmodified Softmax.
When T→0 approaches argmax (fully deterministic) and T→∞ approaches uniform distribution.

What is the role of AutoTokenizer and AutoModelForCausalLM in the Hugging Face
transformers library? Why must the same tokenizer used during training also be used at
inference time?

### WRITE ANSWER BELOW ###

Different models use different tokenizer schemes. AutoTokenizer automatically detects the tokenizer the model needs and 
loads it. We do not need to specify it manually.

AutoModelForCausalLM

Auto: Auto detecs architecture from model name
Model: The actual transformer Model
for: it attaches an LM head linear layer projecting hidden states → vocab-size logits
causal: left to right
LM: Language model that predicts token

This is used for next token prediction based on probability.
Casual because it only sees the left i.e past tokens never future tokens.
LM head:  logits → softmax gives a probability distribution
from_pretained options loads weights into memory with options of control precision



The same tokenizer is used at interence time because diffent model uses different tokenization method like 
BERT: wodpiece, GPT2: BPE, LLaMa: Sentencepiece , phi3: Tiktoken style BPE and so on.

Vocab ↔ embedding alignment : Specific token id maps to specific row in embedding matrix.A different tokenizer assigns different 
IDs to different strings. So decoding with different tokenizer would generate completely meaningless embedding.

Special tokens : Special tokens like <|endoftext|>,<|CLS|> have specific IDs baked during training due to position/attention.
Mismatched special-token ids corrupt the sequence boundaries.
